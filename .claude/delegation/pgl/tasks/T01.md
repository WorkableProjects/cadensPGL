# T01 — Guest wishlist UI

## Goal
Build the public, family-facing wishlist page for Caden's Personal GiftList. It renders every item from the live CSV as an attractive card, has a detail view, search, filters, counts, three text-size modes, polished animations, and an honest "mark as purchased" flow. Read `/plan.md` sections 2–5 and 8 for the product intent; this spec overrides plan.md wherever they differ (notably: GitHub Pages only, no server).

## Page structure (index.html)
- `<html lang="en" data-text-size="normal">`. In `<head>`, a tiny inline script that reads `localStorage['pgl.textSize']` (try/catch) and sets `data-text-size` before paint.
- Google Fonts: Nunito (400,600,700,800) and Fraunces (600,700) via `<link>`; tokens.css already names them with fallbacks.
- `<link rel="stylesheet" href="assets/css/tokens.css">` then `assets/css/app.css`.
- `<script src="vendor/papaparse.min.js"></script>` then `<script type="module" src="assets/js/app.js"></script>`.
- Title from CONFIG.title (set `document.title` and the `<h1>` in JS; put "Caden's Gift List" in the static HTML too).
- Header: h1 title, welcome text (CONFIG.welcome), a one-line helper "Tap a gift to see why I want it and where to buy it."
- Toolbar (sticky-ish is fine, not required): search input with a visible label; filter segmented control All / Available / Purchased (buttons with `aria-pressed`, showing counts e.g. "Available (11)"); text-size segmented control Normal / Bigger / Biggest (`role="radiogroup"` with `role="radio"` + `aria-checked`, or buttons with aria-pressed — label it "Text size"); "Refresh list" button; "Last updated 3:42 PM" text (from `loadedAt`, `<time datetime>`).
- Stats line: "13 gifts · 11 available · 2 purchased" (live, `aria-live="polite"`).
- Status banner region (`role="status"`) for cached/error/purchases-unavailable messages.
- `<main>` with the card grid (`<ul>` of `<li>` cards).
- Detail view: native `<dialog>` element (use `showModal()`; Escape closes; focus returns to the card that opened it; close button labelled "Close").
- Small footer: link "List keeper tools" → `admin.html` (low-key, muted).

## Cards
Each card is an `<li>` containing an `<article>`. Clicking the image/title (a real `<button>` covering the card's heading region, or the title as a button) opens the detail dialog. Content in order:
- Image area: fixed aspect ratio 4:3 (`aspect-ratio`), `object-fit: contain` on a soft `--surface-2` background, `loading="lazy"`, `alt` = item title. Implement image fallback: try `item.images[0]`; on `error` try the next; when exhausted (or the array is empty) show a placeholder: a soft gradient tile with a gift SVG icon and the first letter(s) of the title — decorative, `aria-hidden`, card still labelled by its title.
- Badges row: "★ Most wanted" (gold, text + icon) when `item.mostWanted`; status badge always: "✓ Purchased" (success), "◐ 1 of 2 purchased" (warning) or "Available" (brand-soft). Status must be text + icon, not color alone.
- Title (h2/h3, clamp to 3 lines on the card with `-webkit-line-clamp`; full title in dialog).
- Price row (`item.priceText`) — omit entirely when empty. Show "Qty: 2" when quantity > 1.
- Description (`item.description`) — omit when empty, clamp 3 lines.
- "Why I want it" section: heading text "Why I want it" + `item.reason`, clamp ~4 lines on card — omit the whole section when reason is empty. NEVER invent text.
- Tags as small pills — omit when empty.
- Actions:
  - Primary: "Buy this gift" anchor (`<a class="btn btn-primary" href=item.url target="_blank" rel="noopener noreferrer">`) with a visually-hidden "(opens in a new tab)". If `!item.url`: a disabled-looking non-interactive note "Purchase link not available" (not a button). If state is 'purchased': replace primary with a calm "Already purchased" text (no buy link).
  - Secondary: "Mark as purchased" button (only when state !== 'purchased'). Plus "Details" button that opens the dialog.
  - If `status.local > 0`: show a small note "You marked this on this device" with an "Undo" button (calls `clearLocalMark`).
- Purchased cards stay visible (unless filtered), appear completed: reduced saturation on the image, subtle check overlay, muted title. Do not lower text contrast below AA.

Clicking "Buy this gift" must NOT change purchase state.

## Detail dialog
Large image (same fallback logic), full title, price, "Quantity wanted: N" when > 1, status with the "x of y purchased" label, most-wanted badge, full description, full "Why I want it" text (no clamp), tags, Buy button (same rules), Mark as purchased button, Undo for local marks, Close button. Scrollable on small screens; on narrow viewports it should be near full-screen (sheet style). Animate open (fade + scale/slide up) and close (reverse; wait for `animationend`/transitionend or a timeout before calling `dialog.close()`); backdrop fades. Respect reduced motion (tokens.css already shortens durations).

## Mark-as-purchased flow
1. Click "Mark as purchased" → open a confirmation (second `<dialog>`, or a confirm panel inside the detail dialog). Text: "Did you buy “<title>”?" and explanation: "This marks it as bought on this device right away. So everyone else sees it too, please let the list keeper know." If `item.quantity - status.purchased > 1`, include a number input "How many did you buy?" (min 1, max remaining, default 1).
2. Buttons: "Yes, I bought it" (primary) and "Cancel".
3. On confirm: `addLocalMark(id, qty)`; if it returns false show an error message in the dialog ("Couldn't save on this device…"). On success: recompute and re-render the card, counts, filters, and open detail dialog immediately; play a short celebratory animation on the card (e.g. check-mark pop + a few confetti dots, CSS only, skipped under reduced motion); show a success toast "Marked as purchased. Thank you!" and, if `CONFIG.ownerContact` is non-empty, include a link with `CONFIG.ownerContactLabel` pointing to it.
4. Undo: `clearLocalMark(id)` then re-render; toast "Undone."

Toasts: a fixed region `role="status" aria-live="polite"`, auto-dismiss ~5s, dismiss button.

## Search / filter / sort
- Search filters (debounced ~150ms) by case-insensitive match on title, description, reason, tags, category.
- Filter All / Available (state !== 'purchased') / Purchased (state === 'purchased').
- Sort: most-wanted first, then CSV order (`item.order`); purchased items go after non-purchased within "All".
- Counts recalc from the loaded items (counts ignore search; they reflect the whole list).
- Persist the filter choice in sessionStorage (optional).
- Empty states, each distinct and friendly: (a) no results for search/filter — "No gifts match “xyz”." with a "Clear search" button; (b) the CSV genuinely has zero items (status 'ok' and items.length===0) — "The list is empty right now. Check back soon!"; (c) load error (status 'error') — error illustration, the `error` message, and a "Try again" button. Never show (b) for an error.
- Animate filter/search changes: cards fade/scale in with a small stagger (cap total stagger at ~300ms). Avoid big layout shifts.

## Loading & refresh
- Initial: show skeleton cards (6, shimmering, `aria-hidden`) plus visually-hidden "Loading gifts…" in a live region.
- Call `loadWishlist()`. Keep an AbortController; abort any in-flight load before starting a new one (catch AbortError silently).
- `status === 'cached'`: render items and show a warning banner with `result.error` and "Try again".
- `result.purchasesUnavailable && status === 'ok'`: small info banner "Purchase status couldn't be loaded; some gifts may already be bought."
- Refresh button: shows a spinner + "Refreshing…" while loading (button `aria-busy`, disabled), then "Updated" success state for ~1.5s. On failure keep the current list displayed and show the error banner (do not wipe the grid).
- Background refresh every `CONFIG.refreshIntervalMs` when > 0 and `document.visibilityState === 'visible'`, also on `visibilitychange` to visible if last load > 60s ago. Skip background refresh while any dialog is open. Background refresh must be silent (no skeletons).
- Re-rendering after refresh should keep scroll position and not re-animate unchanged cards (keying by item.id is the simple approach: rebuild is fine but only animate cards whose id is new).

## Text-size control
Normal / Bigger / Biggest. On change: set `document.documentElement.dataset.textSize`, save to `localStorage['pgl.textSize']` (try/catch), update aria state. Smoothly animate (e.g. brief fade of the grid) — optional. At Biggest the grid must be a single column (tokens set `--card-min: 100%`) and toolbar controls wrap without horizontal scroll.

## Visual direction
Warm, friendly, family feel: cream background (`--bg`) with a subtle decorative header (soft radial gradients or a gentle confetti/ribbon SVG pattern in brand-soft/gold-soft — tasteful, not busy). Display font Fraunces for h1 and card titles; Nunito for everything else. Cards: `--surface`, `--radius`, `--shadow-sm`, 1px `--border`; hover/focus-within lifts (translateY(-3px), `--shadow-md`) with `--dur` and `--ease-out`. Grid: `grid-template-columns: repeat(auto-fill, minmax(min(var(--card-min), 100%), 1fr))`. Most-wanted cards get a subtle gold ring/top accent. Page entrance: header and toolbar fade-up; cards stagger in.

## Buttons
`.btn` base: min-height `var(--control-h)`, padding `0 var(--control-pad-x)`, `--radius-pill`, font-weight 700, `--fs-sm`/`--fs-md`. Variants: primary (brand bg, brand-contrast text), secondary (surface bg, border, text), ghost. States: hover (darken/raise), `:focus-visible` (tokens provide outline), `:active` (scale .97), `[disabled]`/`aria-disabled` (opacity .55, no pointer), loading (`aria-busy="true"` shows an inline spinner, keeps width), success (brief check). Every button does something real. No icon-only buttons without visible text (the dialog close may be "✕ Close").

## Security
Never use `innerHTML` with CSV-derived strings. Build DOM with `document.createElement` + `textContent`, or a tiny `h(tag, attrs, ...children)` helper that only sets text via textContent. URLs come pre-validated from model.js (`item.url` is http(s) or null); image `src` values come from `item.images`.

## Accessibility
Semantic landmarks (header, main, footer), one h1, cards headed by h2. Visible labels for search. Dialog: `aria-labelledby` its title. Focus visible everywhere. Live regions as described. No horizontal scrolling at 320px width in all three text sizes. Contrast AA (use token pairs as intended: text on surface, brand-contrast on brand, gold on gold-soft, success on success-soft, warning on warning-soft).
