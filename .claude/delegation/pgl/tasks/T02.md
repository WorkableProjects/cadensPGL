# T02 — List keeper (admin) page

## Goal
Build `admin.html`: the owner's tool to (1) import a GiftList CSV with validation + preview and publish it as the canonical `data/wishlist.csv`, (2) record/correct shared purchase status in `data/purchases.csv`, (3) upload item images, (4) see data-loading problems. The site is static on GitHub Pages (no server). Publishing uses a GitHub token the owner pastes at runtime; without a token everything can be downloaded for a manual commit. Read `/plan.md` sections 7, 8, 9 for intent; this spec overrides plan.md where they differ.

## Owns (create/edit only these)
- `admin.html`
- `assets/css/admin.css`
- `assets/js/admin.js`
- `assets/js/admin/*.js` (optional modules)

## Read-only context (do NOT edit)
- `/plan.md`, `.claude/delegation/pgl/PLAN.md`

- `assets/js/model.js` — `buildWishlist(headers, rows) -> {items, issues, missingColumns, unknownColumns}`; `canonicalize(headers, rows) -> {columns, rows}`; `buildPurchases(rows) -> Map`; `PURCHASE_COLUMNS`; `computeStatus(item, record, 0)`; `REQUIRED_COLUMNS`
- `assets/js/data-service.js` — `loadWishlist()` (current live data incl. `purchases` Map and `issues`)
- `assets/js/github.js` — `getToken()`, `setToken(t)`, `verifyToken(t) -> full_name`, `commitFile({token, path, text|base64, message}) -> commit url`, `blobToBase64(blob)`

- `vendor/papaparse.min.js` — load via classic `<script>` before the module script.

## Page layout
`<html lang="en">`, `<meta name="robots" content="noindex">`, same fonts/tokens as guest page (Google Fonts Nunito + Fraunces), `assets/css/admin.css`. Header: "List keeper tools" h1, link back "← Back to the gift list" (`index.html`). A short note: "Family members never need this page. Changes here are saved to the repository's main branch and appear on the gift list after a refresh."

Sections (cards stacked vertically, max-width ~960px):

### 1. GitHub connection
- Explain: "To publish changes directly, paste a fine-grained GitHub token with **Contents: Read and write** access to `<owner>/<repo>`. It stays in this browser tab only and is forgotten when you close it." Link to https://github.com/settings/personal-access-tokens/new (target=_blank rel=noopener).
- Password input + "Connect" button → `verifyToken` → on success `setToken`, show "Connected to <full_name>" + "Disconnect" button (clears token). Show errors from verifyToken verbatim.
- If not connected, publish buttons elsewhere are replaced by/accompanied with "Download file" buttons and instructions: "Commit this file to `data/wishlist.csv` on the main branch."

### 2. Current list health
- Loads live data via `loadWishlist()` on page load + a "Reload" button. Show: source (main / site copy / cached), loaded time, item count, and a table/list of `issues` (level icon + text, warnings vs errors). Specifically highlight unresolved images count.

### 3. Import a GiftList CSV
- File input (accept `.csv,text/csv`) + drag-and-drop zone. Read with `file.text()`.
- `parseCsv` → `buildWishlist`. Preview:
  - Missing required columns → blocking error, cannot publish.
  - Unknown columns → info "These extra columns will be kept: …".
  - Parse errors and issues list (errors block nothing by themselves except missing columns, but show "N rows will be skipped").
  - Summary: "13 items ready to import (2 most wanted)". Diff vs current live list by gift_id: added / removed / changed (title, url, price, notes, image changed) counts with expandable names.
  - Preview table: thumbnail-less rows: title, price, qty, most wanted, tags, has link?, image status.
  - Removed items note: "Their purchase records will be archived, not deleted."
- Actions: "Publish to main" (requires token; confirm dialog "Replace data/wishlist.csv on main with N items?") and "Download wishlist.csv". Both use `canonicalize(headers, rows)` + `toCsv(rows, columns)` — output keeps ALL rows that have content (canonicalize includes every row; do not drop rows here — validation issues are displayed, the guest site skips invalid rows itself).
- After publishing a new wishlist, also update purchases.csv: for gift_ids that are in purchases but no longer in the new list set `archived=TRUE`; for ids back in the list set `archived=FALSE`. Commit purchases.csv only if it changed. Commit message: "Update wishlist from GiftList import (N items)".
- Loading/success/error states on every button (spinner + aria-busy; success shows link to the commit url).

### 4. Purchase status (shared for everyone)
- Table of live items (from loadWishlist): title, wanted qty, number input "purchased" (0..quantity), state label via computeStatus(item, record, 0), last updated. Most wanted first, then CSV order.
- Archived records (ids in purchases not in the list) in a collapsible "Archived (removed from list)" section, read-only with a "Delete record" button.
- Editing marks rows dirty (highlight). "Save purchase status" → builds purchases.csv rows from all records: columns `PURCHASE_COLUMNS`; `updated_at` = now (ISO) for changed rows only, preserved otherwise; omit rows where purchased=0 and reserved=0 and not archived. Publish (token, commit message "Update purchase status") or download. Confirm before publish. "Reset changes" button.
- Helper text: "When a family member tells you they bought something, record it here so everyone sees it."

### 5. Item images
- Explain the GiftList export's images are relative `media/...` paths that can't be loaded, so upload a picture per item (save the product image from the store page).
- For each live item: current image preview (try `item.images` in order with onerror fallback, else "No image" placeholder), and a file input (accept image/webp,image/jpeg,image/png; max 2 MB, validate) → preview → "Upload" (token required) commits to `${CONFIG.imagesDir}/${gift_id}.<ext>` (ext from MIME: webp/jpg/png) using `blobToBase64`, message "Add image for <title>". Without token: show the exact target path to commit the file to manually and offer a download of the file renamed to that name.
- Note: the guest site tries `.webp`, then `.jpg`, then `.png`.
